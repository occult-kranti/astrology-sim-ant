# Desktop source assistant

The primary workflow is a question, inspectable source evidence and an optional chart proposal. Keep that path usable without a model, account or network. The desktop chart remains the authoritative calculated state; the assistant can only request a change through its narrow preview/Apply bridge.

The existing black instrument desk extends into a two-column section: question, answer and source passages on the left; connection and disclosure controls on the right. Cyan identifies actionable study controls. Muted amber identifies corpus scope; it is not a prediction score. At narrow widths the columns become an ordered flow with the question and answer first, followed by optional settings. Native details keep lengthy configuration secondary. The section retains one heading, visible labels, status announcements and clear keyboard focus.

The visible states are local/no match, prepared/not sent, waiting/stoppable, answer/citation review, proposed/not applied, applied, stale and failed/retryable. A typed question, changed chart or manual action supersedes older work. Stop or a late response never applies a model action. A proposal is tied to the current revision, including unsaved setting edits. The action payload and outbound model request remain available for inspection before execution or transmission.

Questions and model prose are plain text. Citation cards show canonical passages, stable identifiers, locators, rights scope and reading depth. Provider-supplied URLs and self-reported citation validity do not override the local source index. Supabase rows are separately labelled remote reference data and require verified content hashes. No service connection is attempted on mount.

The user can enable chart context separately from a general question. The disclosure names dates, clocks, locations and chart settings. Saved chart libraries, browser credentials and conversation history are excluded. Local model setup, paid API credentials, local-app ChatGPT authorization and MCP installation are distinct choices with distinct readiness states.

Acceptance includes desktop and 320px layouts, keyboard actions, inert malicious model text, missing/invented citations, stale proposals, edited structured JSON, exact request-body disclosure, changed-chart cancellation, late Supabase replies, bounded errors and real file-origin offline operation. These are engineering checks, not a human usability study or evidence for astrological prediction.
