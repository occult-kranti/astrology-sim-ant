## CI transport finding and corrected acceptance

PR CI run `41006931104` rejected the candidate in the inherited 130-page sweep: Event Horizon emitted `net::ERR_ABORTED` events before teardown even though its complete preset could validate and activate. The dedicated browser driver had observed console/page errors and HTTP failure statuses, but had **not registered `requestfailed` events**. Its earlier zero-error claim was limited to those recorded categories. The original receipts and the inherited gate's rejection are retained; successful data parsing does not establish clean transport completion.

Repeated Chromium 145 experiments isolated the behavior to manual consumption of the original response stream. Releasing its reader, retaining the response and inserting asynchronous yields did not reliably remove the failures. The corrected loader consumes the original response through native `arrayBuffer()` and monitors a cloned stream to enforce the byte limit during transfer. A per-request controller retains caller cancellation and closes oversized transfers, with an explicit size error taking precedence over the resulting abort. The regenerated source binding is **`0d63dab6c7efeb79515bc985d305ea09e8bd356bf45c5be9db175a69fe8ed9aa`**; manifest SHA-256 is **`970d6cb7077854be230c3d903b706fab74ab5616deb75ccc6f4fc57204aefed3`**. The source owner's separate parity audit confirms all four data parts remain byte-identical to the preceding candidate.

The new `scripts/tests/horizon-loader.mjs` passed **nine real-HTTP checks** using native fetch and actual AbortSignals, both on Node24.19.0 and the CI-matching Node22.23.4 runtime. It loads the complete release, rejects oversized chunked manifests and case parts before the server finishes sending them, checks size-error precedence, pre-aborted and mid-read cancellation, full recovery, truncation and same-length corruption. In the retained run the server stopped at 1,081,344 of 3,145,728 attempted manifest bytes, 9,732,096 of 11,798,752 attempted oversized case bytes, and 32,768 of 9,701,600 bytes after caller cancellation. These are observed transport stops, not a claim of a byte-exact process-memory ceiling. [HTTP evidence](evidence/horizon/transport-correction/loader.json) and the [Node22 receipt](evidence/horizon/transport-correction/loader-node22.json) record unchanged source and artifact hashes.

The strengthened browser run passed **700 checks, 28 actual downloads, 36 screenshots and eight font diagnostics** at 320, 390, 1440 and 1920 pixels. There were **zero unexpected request failures**, console/page errors, missing responses, external requests or source drift. Four `ERR_ABORTED` events are retained and individually attributed to the exact manifest Request deliberately held and cancelled by the test—one per width. No broad abort exemption was added.
