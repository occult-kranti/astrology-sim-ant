Baseline `fb656a8047e93b8d49227d92aa9edc3e9b1fce50`; six-role panel, UI implementation member. The design contract is [the sky explorer design record](../.design/sky-explorer.md). This is an AI-agent design review, not human usability research.

## Round 1: implementation and early cross-review

The new shared component mounts on the main atlas and all five existing family pages. It keeps the comparison ledger, birth privacy boundary, existing plate and exports while adding a primary interactive deep chart, a heliocentric position projection, visible local interpretations, selected calendar overlays, clock-alignment differences, manual ICS preview and a calculated timeline.

Code-derived findings corrected during the first implementation:

| Finding | Consequence | Correction | Acceptance check |
|---|---|---|---|
| Overlay sectors already contained the tropical origin | Applying the sidereal offset twice would draw the wrong boundaries | Draw supplied physical tropical angles directly | Compare rendered ring marks with core sector angles |
| Worker IDs required strings | Numeric UI IDs could leave a rejected job appearing busy | Use bounded string IDs with a separate local generation counter | Actual build completes; cancellation discards stale replies |
| Input invalidation erased the previous zone before comparison | Old-zone local labels could become active after recasting | Compare retained timeline request zone with the new input | Zone change requires timeline rebuild |
| Timeline options did not invalidate work | Export could refer to prior settings | Cancel and clear on form edit | Edited controls disable old exports |
| Coarse Moon sampling warnings were hidden | Connected samples could look like continuous motion | Visible warning above the plot | Coarse window exposes aliasing limits |
| SVG redraw removed the focused body marker | Keyboard navigation could restart after selection | Restore focus to the same newly rendered marker | Enter/Space changes selection and retains focus |
| “Apparent altitude” labelled an unrefracted calculation | Meaning overstated the physical model | Use “Geometric altitude” and visibility scope | Display matches `refraction: none` contract |

The inherited Sun–Moon geometry gate must explicitly select its retained tab. It still verifies the original geometry and exported bytes; it is not weakened to accommodate a new display.

Runtime verification is pending the integrated candidate. Later rounds will record actual browser evidence, source hashes, correction results and remaining limitations here.

### R2 comparison-to-AI correction

The independent QA role found a substantive mismatch after applying a New York same-clock comparison: the visible comparison had a four-hour difference, while the optional AI packet silently used the default same-zone, same-instant comparison. The parent component now passes the **applied** comparison zone, clock mode and ambiguity choice into the assistant's preparation and invalidation fingerprint.

Pending comparison edits clear the old rings and comparison ledger and disable the combined reading JSON and AI preparation until Apply. The assistant's readiness callback checks the same dependency for copying and sending. Switching overlays off discards that comparison context; local reading JSON has `alignment: null`. Invalid zone input cannot preserve an active old comparison. A neutral section heading avoids calling two intentionally different instants “one instant”; the fixed observer coordinates, exact elapsed seconds, human-readable hours and unverified geographic zone assignment are explicit.

A fresh pinned-Chromium run passed **29 checks and inspected eight actual JSON downloads** at 1440px and 320px, with zero runtime errors. It compared the downloaded AI packet's complete synchronization record to the downloaded local reading, verified the +14,400-second New York difference and reapplied UTC result, checked pending/invalid comparisons and tested overlay-off recovery. [Receipt and file hashes](evidence/sky/ui-round2/alignment-ai.json). This corrects an actual payload inconsistency, not only a label or disabled-button appearance. No real model inference was used.
